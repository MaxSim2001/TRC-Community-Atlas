# TRC Community Atlas 0.11.0 — QA des 179 modules

Date : 2026-10-06  
Portée : catalogue complet des modules, profils métier, formulaires pleine page, persistance et responsive.

## Résultat

- 179 modules catalogués et audités : 9 Core Assets, 22 Apps & Services et 148 types personnalisés.
- 41 profils d’éditeur distincts, incluant les trois éditeurs dédiés Configurations, Locations et Passwords.
- 179 modules sans anomalie de schéma.
- 176 modules à éditeur partagé ou spécialisé validés par rendu de tous leurs champs et aller-retour SQLite.
- 41 profils inspectés dans le navigateur à partir de leur véritable page de création.
- 28 tests automatisés réussis, aucun échec.
- Aucune erreur ni aucun avertissement dans la console navigateur durant la QA.

## Améliorations livrées

Les modules spécialisés ne retombent plus presque tous sur une fiche générique minimale. Atlas possède maintenant des profils adaptés pour les serveurs, postes, stockage, bases de données, équipements et plateformes de sécurité, téléphonie, sécurité physique, équipements OT, installations, cloud, changements, supervision, accès distant, identités, services Web, imprimantes et messagerie.

Le profil polyvalent a aussi été enrichi : fabricant ou fournisseur, modèle, identifiant interne, rôle opérationnel, soutien, maintenance et cycle de vie.

La page **Gérer les modules** affiche maintenant :

- le nombre total de modules;
- le nombre de profils métier;
- le nombre de modules validés;
- le nombre d’anomalies de schéma;
- le profil et le nombre de champs de chaque module.

Les ressources CSS et JavaScript portent aussi la version `0.11.0` dans leur URL afin qu’un navigateur ou un proxy ne conserve pas une interface plus ancienne après un déploiement.

## Défaut trouvé pendant la QA visuelle

`Composant réseau` était classé comme stockage parce que l’ancienne détection reconnaissait la chaîne `san` à l’intérieur de `composant`. La règle exige maintenant les acronymes complets `NAS` ou `SAN`. Un test de non-régression couvre `Composant réseau`, `NAS`, `SAN`, `SQL Server`, `Camera`, `PBX IP`, `Ssl`, `Documents`, `Exchange Server` et `Probe Virtuel`.

## Contrôles automatisés

Pour chaque module :

1. identifiant unique, libellé, groupe et icône;
2. profil métier existant;
3. au moins quatre champs métier utiles;
4. clés de champs uniques;
5. types de contrôles pris en charge;
6. options présentes pour les listes;
7. absence de champ secret dans les fiches ordinaires;
8. rendu HTML de chaque champ attendu;
9. conservation de tous les champs après fermeture et réouverture de SQLite.

Les mots de passe restent dans l’éditeur dédié du coffre AES-256-GCM et ne sont pas inclus dans les fiches de module ordinaires.

## Contrôles visuels

- Bureau : 1280 × 720, aucune barre horizontale globale.
- Mobile : 390 × 844, cartes de gestion lisibles et formulaires sur une seule colonne.
- Chaque profil : formulaire pleine page, pied d’action présent, au moins quatre contrôles visibles, aucune liste de sélection d’organisation et organisation active injectée dans un champ caché.
- Profils spécialisés File Sharing et Printing inclus.
- Formulaires complexes Serveur et Stockage inspectés avec leurs libellés métier complets.

## Isolation

La QA navigateur a été exécutée sur `127.0.0.1:9194` avec un répertoire de données isolé. Aucun compte, secret ou enregistrement de production n’a été utilisé ou modifié. TRC Account et le SSO RMM sont demeurés hors portée et désactivés.
